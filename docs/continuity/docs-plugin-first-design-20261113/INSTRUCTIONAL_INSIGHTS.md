# Instructional insights

## 2026-11-13

1. Deliver documents when requested, with actual paths and readback. Chat summaries are not a report set. Explain mode limitations early; after writes become permitted, finish artifacts without another approval loop.
2. Audit branch-local truth. A feature worktree can differ dramatically from main; label source and baseline revisions in every finding and handoff.
3. Prefer CodeMunch for source and DocMunch for documents. When DocMunch rejects equivalent-corpus reuse, explicit `branch_local` via installed MCP server can restore fresh retrieval without bypassing the requested tool.
4. Inspect worker output before claiming completion. Initial drafts omitted instance identity, exact migration behavior, replay, diagnostics ownership and concrete deployment gates; lead review corrected those.
5. Monitor workers and preserve edits on usage-limit failures. Complete bounded critical-path work inline instead of treating worker termination as the outcome.
6. Separate primary-source facts, architecture inference, historical run evidence and current runtime proof. A live website or upstream main commit is not proof of installed version behavior.
7. Validate using both document-aware checks and Git whitespace checks. Markdown hard-break spaces passed custom validation but failed stricter Git checks; record failed check and correction rather than erase history.
8. Scope continuity by feature branch to avoid clobbering another session's root six-file set. Keep resume point concise and link the detailed dossier.
